# Compatibility and release policy

[Documentation home](index.md) · [Support matrix](support-matrix.md)

Rewind uses independent package and artifact versions. The next package is
`0.2.0a1`; the current artifact schema remains `0.1`. New readers retain data-only
loading of the checked-in artifact generated by published `0.1.0a2`. New required
operations are rejected by readers that do not understand them; a shared schema
number never instructs an old reader to guess their meaning.

## Public contract

Public APIs are the names exported by `rewind`, documented adapter constructors
and methods, and documented CLI commands/options. Underscored modules and
attributes are implementation details. During alpha, API changes may occur:
each release documents them, provides applicable migration guidance, and remains
immutable after publication. There is no stable 1.0 or long-term-support promise.

Strict reproduction requires matching declared source bytes, application name,
Python major/minor, installed supported dependency versions, capture policy,
entry-point kind, ordered interactions, and final outcome. Adding an installed
supported integration can change the fingerprint even if that application path
does not use it. Keep the recording environment's dependency lockfile.

`rewind compare` explicitly permits changed source for a developer-selected
comparison. It does not relax dependency observations or supply a business oracle.
Artifact load compatibility does not guarantee runtime reproduction after an
application or dependency upgrade.

## Release gates

Every candidate must pass Python 3.11/3.12 tests, lint and types, schema fixture
checks, distribution verification, supported real-service conformance and the
network-disabled Docker smoke suite. Synthetic staging budgets and the disable,
drain and rollback drill produce inspectable reports. TestPyPI installation and
wheel-byte verification precede promotion of the same distribution to PyPI.

The documented adapter methods define the deliverable. Distributed scheduling,
process/heap checkpointing, transparent global interception, unsupported SDKs,
and production security certification are not claims made by this release.
A production rollout needs the consuming application's workload and data-policy
review; the bundled local synthetic suite is the requested local validation
profile, not a replacement for those application-specific decisions.
